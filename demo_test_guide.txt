# SmartFactory AI: Demo Test Guide & Architectural Breakdown

This document provides a detailed breakdown of the backend database architecture, the multi-agent pipeline logic, mobile stack specifications, and development connectivity protocols.

---

## 1. WHY WE ARE USING SUPABASE & HOW IT WORKS

### Why We Are Using Supabase
Supabase serves as the core real-time cloud data layer and backend-as-a-service (BaaS) for the SmartFactory AI platform. We selected Supabase for several key reasons:
1. **Relational Integrity for Multi-Agent Data**: The platform manages highly structured, interconnected data (e.g., Scenarios having many Data Sources, Agent Traces, Insights, Contradictions, Actions, and Simulations). Supabase is built on **PostgreSQL**, providing full relational integrity, foreign key constraints, and transactional consistency required to link analysis results correctly.
2. **Real-time Synchronization (WebSockets)**: Supabase has built-in Realtime engine support. Clients (like our mobile dashboard) can subscribe to specific tables (e.g., `agent_traces` or `scenarios`) and instantly receive updates when the backend updates a scenario status or inserts a new agent reasoning step.
3. **Decoupled Architecture**: It serves as a unified database hub. The backend writes analytical results directly to it, making it immediately available.

### How It Works Under the Hood
1. **Database Schema & Tables**:
   Supabase hosts a PostgreSQL database with the following critical tables:
   - `scenarios`: Stores the scenario run state (e.g., `pending`, `running`, `complete`, `error`), title, and general description.
   - `data_sources`: Holds raw and parsed telemetry data (CSV files, operator shift logs).
   - `ml_predictions`: Stores Scikit-Learn or predictive model metrics (e.g., risk scores, failure probability, failure types).
   - `agent_traces`: Records the sequential step-by-step prompts sent to each agent and the raw/parsed JSON responses from the models.
   - `insights`: Stores resolved, structured diagnostic data generated by the Machine Health Agent.
   - `contradictions`: Stores detected conflicts between human logs and physical sensor data.
   - `actions` & `action_steps`: Stores concrete recommendations, cost estimates, efforts, and sequence steps.
   - `simulations`: Stores before/after risk scores, production rates, and simulated metrics.
   - `notifications`: Stores simulated SMS and email payloads.

2. **Backend Connection (Python SDK)**:
   The FastAPI backend uses the official `supabase` Python client. A singleton wrapper (`backend/services/supabase_client.py`) reads the `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` environment variables to authenticate. It provides methods like `insert_row`, `fetch_rows`, and `delete_row` to perform asynchronous queries.

3. **Data Access Pattern**:
   To secure database keys and maintain business logic, the mobile application does **not** talk to Supabase directly. Instead, the mobile client issues REST requests to the FastAPI backend, which handles all business rules and database queries before returning a clean API response to the mobile client.

## 2. DETAILED EXPLANATION OF HOW EVERY AGENT WORKS

The SmartFactory AI system orchestrates a pipeline of **five highly specialized agents** sequentially. The pipeline is managed by `AntigravityOrchestrator` (`backend/agents/orchestrator.py`), which passes variables and states from one agent to the next to build a comprehensive analysis.

### Agent 1: Machine Health Agent (`agent_machine_health.py`)
* **Objective**: Assess factory equipment health by auditing telemetry, detected anomalies, and machine learning model predictions.
* **Inputs**: Raw sensor telemetry (vibration, temperature, torque), ML model predictions (anomaly scores, failure probabilities), and unstructured operator notes.
* **Logic**: It cross-references ML risk scores with raw sensor readings to find subtle operational degradation patterns. It maps evidence to specific machines at risk.
* **Output**: A structured list of risk assessments per machine (risk score, list of anomalies, urgency level, evidence) and an overall factory risk score.

### Agent 2: Contradiction Detection Agent (`agent_contradiction.py`)
* **Objective**: Detect inconsistencies and conflicting information across different data streams (e.g., sensor data vs. operator shift logs vs. supplier emails).
* **Inputs**: Inventory levels, supplier emails, and the Machine Health Agent's output.
* **Logic**: It compares reported maintenance schedules or inventory statuses in emails against actual sensor anomalies and real-time stock levels. It resolves conflicts logically by prioritizing newer or more authoritative sources based on timestamps.
* **Output**: A list of detected contradictions (what field conflicts, what Source A says, what Source B says, the logical resolution, confidence rating, and recommended action).

### Agent 3: Demand Forecast Agent (`agent_demand.py`)
* **Objective**: Predict production impacts and supply chain risks by combining operational status with external factors.
* **Inputs**: External news feeds (e.g., logistics strikes, weather events, fuel hikes), current inventory levels, contradictions resolved by Agent 2, and machine health status from Agent 1.
* **Logic**: It projects how machine downtime or resource inventory shortfalls will impact upcoming schedules. It estimates raw material runway (days remaining) and determines stockout risks.
* **Output**: Quantitative metrics (`demand_delta_pct`, `stockout_risk_pct`, runway days) and qualitative drivers/risks.

### Agent 4: Action Planning Agent (`agent_action_planner.py`)
* **Objective**: Generate concrete, domain-specific, and safe mitigation steps based on all intelligence gathered.
* **Inputs**: Machine Health logs (Agent 1), Contradictions (Agent 2), and Demand/Supply risks (Agent 3).
* **Logic**: Instead of providing generic advice, it translates diagnoses into physical, real-world tasks categorized under Maintenance, Logistics, or Production. It estimates effort hours and cost.
* **Output**: A prioritized array of actions (action ID, title, description, priority, category, effort hours, cost estimate, target system, and step-by-step checklist).

### Agent 5: Simulation Agent (`agent_simulator.py`)
* **Objective**: Predict the consequences of the proposed actions and draft notifications for factory stakeholders.
* **Inputs**: The proposed actions list, current context, and historical agent intelligence.
* **Logic**: It models a digital-twin simulation. For each action, it calculates the "Before" vs "After" delta on system risk scores, production efficiency percentages, and operating costs. It also writes customized messaging (SMS/Email) to notify supervisors.
* **Output**: Simulated outcomes (before/after states, timelines) and stakeholder alert notifications.

## 3. MULTI-PROVIDER AI FAILOVER & FALLBACK LOGIC
To ensure high availability and prevent rate-limiting/quota errors (HTTP 429), the `GeminiClient` (`backend/agents/gemini_client.py`) implements a dynamic provider routing system:
1. **Developer API (Google AI Studio)**: First attempt. Uses `GOOGLE_API_KEY` to call the primary model `gemini-2.5-flash` (or fallbacks `gemini-2.5-flash-lite`, `gemini-2.0-flash-lite`, `gemini-2.0-flash`).
2. **Vertex AI API**: If AI Studio returns a quota or rate limit error, the client dynamically falls back to Vertex AI using `GOOGLE_PROJECT_ID` and credentials.
3. **Groq API**: If both Google services are unavailable or quota-limited, the system falls back to Groq running `llama-3.3-70b-versatile` to successfully complete the pipeline.

## 4. HOW THE MOBILE APP IS CONNECTED TO EXPO GO

Expo Go is a developer application that runs React Native applications instantly on physical devices or emulators without compiling native binary files (like APKs or IPAs) locally.

### Step-by-Step Connection Mechanics
1. **Metro Bundler**: When you run `npm run start` or `npx expo start` in the `mobile/` directory, Expo starts the **Metro bundler** on your computer. Metro compiles the TypeScript source code into a single JavaScript bundle and hosts a local dev server (default port `8081`).
2. **The expo:// Protocol**: The dev server outputs a URL utilizing the Expo protocol, such as `exp://10.108.160.86:8081` (where `10.108.160.86` is the computer's local IP address).
3. **Physical Device Connection (QR Code)**:
   - The developer scans the QR code generated in the terminal using the camera app (iOS) or the Expo Go app (Android).
   - Both the computer and the mobile device **must be on the same local Wi-Fi network**.
   - Expo Go contacts the Metro server at the specified local IP and downloads the bundle into the Expo client.
4. **Emulator Connection**:
   - Pressing `a` or `i` in the terminal tells Expo to deep-link directly to the emulator. It launches the Expo Go app inside the emulator and loads `localhost` or `10.0.2.2` (Android loopback).
5. **Fast Refresh**: Metro maintains a WebSocket connection to the app running inside Expo Go. When code is edited and saved on the computer, the changes are dynamically pushed and refreshed on the phone instantly.

## 5. MOBILE TECH STACK BREAKDOWN

The mobile application is built with a premium, high-fidelity UI. The core stack includes:
* **Framework**: **React Native** managed through **Expo (v54.0.33)** for cross-platform iOS and Android support.
* **Routing & Navigation**: **Expo Router (v6.0.23)** which provides folder-and-file-based navigation (e.g., `app/(tabs)/index.tsx`, `app/(tabs)/input.tsx`).
* **State Management**: **Zustand (v5.0.13)**. It manages global state (scenarios list, current running pipeline status, uploaded data sources) without the boilerplate of Redux.
* **HTTP Client**: **Axios (v1.16.1)**. Handles network requests targeting `EXPO_PUBLIC_API_BASE_URL` (which points to the FastAPI backend API at `http://<computer-local-ip>:8000/api/v1`).
* **CSV Parsing**: **PapaParse (v5.5.3)**. Used on the client-side to parse, validate, and preview CSV sensor files before they are ingested.
* **Graphics & Icons**:
  - **`react-native-svg` (v15.12.1)** for rendering custom vector graphics, donut status charts, and line graphs.
  - **`@expo/vector-icons` (v15.0.3)** for premium material and ionic symbols.
* **Layout Utilities**: `react-native-safe-area-context` and `react-native-screens` to guarantee native-like transitions and respect device notches.
